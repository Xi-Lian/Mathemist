# V48.10 GGB 接口 URL 路径修复（查询参数版本）

## 🐛 问题描述

**错误日志**：
```
INFO:     127.0.0.1:50221 - "POST /langgraph/math-agent/ggb/innovation-suggestions HTTP/1.1" 404 Not Found
```

**根本原因**：
- 前端访问的 URL 包含了 `apiUrl` 查询参数：
  ```
  /combined-geometry?apiUrl=http://localhost:8000/langgraph/math-agent
  ```
- V48.9 修复只处理了环境变量 `NEXT_PUBLIC_API_URL`，但**没有处理查询参数**
- 代码逻辑是：**查询参数优先级高于环境变量**
- 所以即使环境变量已修复，查询参数中的 `/langgraph/math-agent` 仍然会导致错误

**代码逻辑**（修复前）：
```tsx
if (initialApiFromQuery) {
  setApiBaseUrl(initialApiFromQuery);  // ❌ 直接使用，包含 /langgraph/math-agent
} else {
  const envUrl = process.env.NEXT_PUBLIC_API_URL || "http://localhost:8000";
  const baseUrl = envUrl.replace(/\/langgraph\/math-agent$/, "");  // ✅ 已修复
  setApiBaseUrl(baseUrl);
}
```

---

## ✅ 修复方案

### 修复：统一处理查询参数和环境变量

**文件**: `frontend/src/components/geometry/CombinedGeometryWorkbench.tsx`

**修改后**（第30-48行）：
```tsx
// 在客户端挂载后初始化 apiBaseUrl
useEffect(() => {
  const initialApiFromQuery = searchParams.get("apiUrl")?.trim() ?? "";
  // V48.9修复：GGB接口不使用包含 /langgraph/math-agent 的 URL
  // 无论是查询参数还是环境变量，都需要提取基础 URL
  let baseUrl: string;
  
  if (initialApiFromQuery) {
    // 从查询参数中提取基础 URL（去掉 /langgraph/math-agent）
    baseUrl = initialApiFromQuery.replace(/\/langgraph\/math-agent$/, "");
  } else {
    // 从 NEXT_PUBLIC_API_URL 中提取基础 URL（去掉 /langgraph/math-agent）
    const envUrl = process.env.NEXT_PUBLIC_API_URL || "http://localhost:8000";
    baseUrl = envUrl.replace(/\/langgraph\/math-agent$/, "");
  }
  
  setApiBaseUrl(baseUrl);
  setIsMounted(true);
}, [searchParams]);
```

**关键改进**：
1. **统一处理逻辑**：无论来源是查询参数还是环境变量，都执行相同的清理操作
2. **正则表达式替换**：使用 `/\/langgraph\/math-agent$/` 匹配并移除后缀
3. **提前声明变量**：使用 `let baseUrl` 避免重复调用 `setApiBaseUrl`

## 📝 技术细节

### 正则表达式说明

```javascript
/\/langgraph\/math-agent$/
```

- `\/`：转义斜杠 `/`
- `langgraph`：匹配字符串 "langgraph"
- `\/`：转义斜杠 `/`
- `math-agent`：匹配字符串 "math-agent"
- `$`：锚定到字符串末尾

**示例**：
```javascript
"http://localhost:8000/langgraph/math-agent".replace(/\/langgraph\/math-agent$/, "")
// → "http://localhost:8000"

"http://localhost:8000".replace(/\/langgraph\/math-agent$/, "")
// → "http://localhost:8000"（不匹配，保持不变）
```

### 为什么需要同时处理两种来源？

1. **查询参数来源**：
   - 用户可能从其他页面跳转过来，URL 中携带了 `apiUrl` 参数
   - 例如：从 LangGraph Playground 跳转到 GGB 工作台

2. **环境变量来源**：
   - `.env.local` 文件中配置了默认 API URL
   - 当 URL 中没有查询参数时使用

3. **优先级设计**：
   - 查询参数 > 环境变量 > 默认值
   - 这样用户可以灵活覆盖默认配置

## 📋 总结

**问题原因**：
- URL 查询参数 `apiUrl` 包含了 `/langgraph/math-agent` 后缀
- V48.9 只修复了环境变量，没有修复查询参数
- 查询参数优先级更高，导致修复未生效

**解决方法**：
- 统一处理查询参数和环境变量
- 都使用相同的正则表达式去除后缀
- 确保最终 URL 是基础 URL（不含 `/langgraph/math-agent`）

**验证方法**：
- 硬刷新浏览器页面
- 检查 Network 标签中的请求 URL
- 确认状态码为 200 OK

现在 GGB 接口应该能正常调用了！🎉
