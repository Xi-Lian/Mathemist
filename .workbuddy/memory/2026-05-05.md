# 2026-05-05 工作记录

## 修复 retrieve.py 中 KG 节点匹配失效问题（思路A）

### 问题描述
`core_theme` 经 LLM 拆分后变成逗号拼接字符串（如 `"三角函数的图象,三角函数的性质"`），作为整体无法匹配 KG 节点的 label（`"三角函数的图像与性质"`），导致 KG 扩展匹配节点数=0，知识点标签过滤失效。

### 修复方案（思路A）
在 KG 匹配前，将 `core_theme` 拆分为独立子主题列表，**逐个子主题独立匹配** KG 节点。

### 改动位置
`backend/app/core/retrieval/methods/retrieve.py` 第244-305行区域

### 具体改动
1. **拆分 core_theme**：兼容 `list` 和 `str` 两种输入，str 按逗号拆分为 `_theme_parts` 列表
2. **逐个标准化**：对 `_theme_parts` 中每个子主题独立做同义词映射（`图象` → `图像`）
3. **逐个匹配**：label 匹配和 keywords 匹配都改为对 `_theme_parts` 遍历，任一个子主题匹配即命中
4. **逐个加入 kg_keywords**：将每个子主题（原始+标准化）独立加入，而非整个逗号串
5. **优化日志**：新增输出 `子主题=` 和 `子主题(标准化)=`，方便调试

### 预期效果
- `"三角函数的图像"` 能通过 `startswith` 匹配 KG 节点 `"三角函数的图像与性质"`
- `matched_node_ids` 不再为空，KG 扩展能拿到后代节点的 keywords
- 习题的 `kg_match` 标签能正确标注

### 待验证

- [ ] 验证其他主题（如"向量数量积与向量积"）是否也有类似问题

### 经验教训
- LLM 输出结构不确定（可能拆分/不拆分），代码需兼容两种情况
- KG 节点 label 是完整名称，匹配时 `startswith` 比 `==` 更通用
- 逗号拼接字符串不适合直接用于匹配，应先拆分
