# V41.7 标题字段检查改进总结

## 📋 问题描述

用户反馈："我已知肯定有两个资源是符合我的查询要求的，但是现在只显示了一个"

**查询**："我想要棱柱的练习课课件"

**当前返回**：只返回1个课件
- ✅ `8.1课时1 棱柱、棱锥和棱台` - 得分0.767

**用户期望**：应该返回2个课件
- ✅ `8.1课时1 棱柱、棱锥和棱台`
- ❓ 第2个课件是什么？

---

## 🔍 问题分析

通过数据库查询发现，确实有2个课件与"棱柱"相关且是"练习课"：

### 课件1
```
文件名: 8.1课时1 棱柱、棱锥和棱台
教学用途: 练习课课件
内容: 课时1 棱柱、棱锥和棱台
```
✅ **文件名包含"棱柱"** → 通过早期拒绝检查

### 课件2（courseware_849）
```
文件名: 8.1课时2 圆柱、圆锥、圆台和球
标题: 8.1课时2 圆柱、圆锥、圆台和球 - 课时2 棱柱、棱锥、圆台和球
教学用途: 练习课课件
内容: 课时2 棱柱、棱锥、圆台和球
```
❌ **文件名不包含"棱柱"** → 被V41.6的早期拒绝机制过滤掉
✅ **但标题包含"棱柱"** → 应该被接受

### 根本原因

V41.6的早期拒绝机制只检查了`filename`字段：

```python
filename = metadata.get('文件名', '') or metadata.get('title', '')
# 如果'文件名'字段存在，就使用它，不会使用'title'

if not has_core_in_filename:
    return 0.0, False, details  # 直接拒绝
```

对于courseware_849：
- `文件名`字段：`"8.1课时2 圆柱、圆锥、圆台和球"`（不包含"棱柱"）
- `title`字段：`"8.1课时2 圆柱、圆锥、圆台和球 - 课时2 棱柱、棱锥、圆台和球"`（包含"棱柱"）

由于`文件名`字段存在，所以使用了它，导致检查失败。

---

## ✅ 解决方案

### 核心改进：同时检查文件名和标题两个字段

在早期拒绝检查时，不仅检查`filename`，还要检查`title`字段。只要其中一个包含核心主题，就认为通过检查。

### 修改代码

```python
# V41.7改进：对于课件资源，文件名或标题必须包含核心主题或其高度相关词
# 否则直接拒绝，不允许其他字段补偿
if core_theme and (filename or title):
    has_core_in_filename_or_title = False
    themes = [t.strip() for t in core_theme.split(',') if t.strip()]
    
    # 检查文件名和标题两个字段
    fields_to_check = [filename, title] if title else [filename]
    
    for field_text in fields_to_check:
        if not field_text:
            continue
            
        for theme in themes:
            # 精确匹配
            pattern = r'\b' + re.escape(theme) + r'\b'
            if re.search(pattern, field_text, re.IGNORECASE):
                has_core_in_filename_or_title = True
                break
            # 模糊匹配
            if theme in field_text:
                has_core_in_filename_or_title = True
                break
        
        if has_core_in_filename_or_title:
            break
    
    # ... 关键词检查逻辑类似 ...
    
    # 如果文件名和标题都没有核心主题相关内容，直接拒绝
    if not has_core_in_filename_or_title:
        return 0.0, False, details
```

### 关键特点

1. **双字段检查**：同时检查`filename`和`title`
2. **任一通过即可**：只要其中一个字段包含核心主题，就通过检查
3. **保持严格性**：如果两个字段都不包含核心主题，仍然拒绝
4. **向后兼容**：对于没有`title`字段的资源，仍然只检查`filename`

## 💡 设计思考

### 为什么要同时检查文件名和标题？

1. **数据不一致性**：有些资源的`文件名`和`title`字段内容不同
   - `文件名`可能是简短的文件名
   - `title`可能是更详细的描述

2. **用户体验**：用户关心的是资源的内容，而不是字段的名称
   - 只要资源的标识（文件名或标题）中包含核心主题，就应该被认为是相关的

3. **保持严格性**：仍然要求至少一个标识字段包含核心主题
   - 不是完全放宽，而是更灵活地检查

### 为什么不检查内容字段？

1. **内容字段可能过于宽泛**：内容中提到的主题不一定是主要主题
2. **文件名/标题更直观**：用户首先看到的是文件名或标题
3. **防止误匹配**：如果只因为内容中提到就返回，可能会返回很多不相关的资源

### 平衡点

- **太严格**：只检查文件名 → 可能漏掉相关资源（如courseware_849）
- **太宽松**：检查所有内容 → 可能返回太多不相关资源
- **平衡方案**：检查文件名和标题 → 既保证相关性，又避免遗漏
