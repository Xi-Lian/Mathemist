# V48.5 全新需求提取净化 - 防止旧信息污染

## 🐛 问题描述

**用户输入序列**：
```
用户1：帮我生成一个函数单调性的教案
系统：[生成了函数单调性教案]

用户2：下周有个示范课观摩活动，主题是概率统计，需要规范的教案，帮我生成教案
系统：❌ 教案已经完整生成了！
      目前这份《函数的单调性》教案涵盖了...
```

**根本原因**：
1. V48.3清空了`session["collected_info"]`
2. 但LLM在提取信息时看到了**对话历史**（包含"函数单调性"）
3. LLM可能从对话历史中错误地提取出旧的topic
4. `extracted`变量包含了旧信息
5. `session["collected_info"].update(extracted)`后，仍然有旧topic
6. 教案生成时使用了错误的topic

---

## ✅ 修复方案

### 修复1：提示词增强 - 明确要求忽略旧课题

**文件**: `backend/app/core/unified_lesson_plan/methods/extract_lesson_plan_info.py`

**新增内容**（第107-116行）：
```python
## 重要提醒：
1. **全新需求 vs 修改需求**：
   - 如果是**全新需求**（用户提出了新课题）：**必须忽略对话历史中的旧课题**，只从最新用户输入中提取信息
   - 如果是**修改需求**（用户在现有教案上修改）：**保留已有信息**，只输出需要修改的字段
2. **全新需求的判断标准**：
   - 用户输入中出现了明确的课题名称（如"概率统计"、"三角函数"等）
   - 这个课题与对话历史中的课题不同
   - 例如：历史中是"函数单调性"，用户说"概率统计" → 全新需求
```

**关键改进**：
- ✅ 明确告诉LLM在全新需求时要**忽略对话历史**
- ✅ 提供清晰的判断标准和示例
- ✅ 强调"只从最新用户输入中提取"

---

### 修复2：代码净化 - 过滤extracted中的旧字段

**新增逻辑**（第159-169行）：
```python
# V48.5增强：确保extracted中只有新提取的字段，移除可能的旧字段
# 只保留从最新用户输入中提取的字段
cleaned_extracted = {}
for key, value in extracted.items():
    # 如果是topic或其他核心字段，保留
    if key in ["topic", "student_level", "class_hours", "teaching_methods", 
               "teaching_goals", "key_points", "difficulties", "usage_scenario"]:
        cleaned_extracted[key] = value
extracted = cleaned_extracted
print(f"✅ 清理后的提取结果: {list(extracted.keys())}")
```

**工作原理**：
1. 检测到全新需求后
2. 创建一个新的`cleaned_extracted`字典
3. **只保留核心字段**（topic、student_level等）
4. 丢弃其他可能的旧字段
5. 用清理后的结果替换原extracted

**允许保留的核心字段**：
```python
ALLOWED_FIELDS = [
```

## 🎯 边界情况处理

### 情况1：LLM提取了额外字段

**LLM输出**：
```json
{
    "topic": "概率统计",
    "usage_scenario": "public_class",
    "old_topic_from_history": "函数单调性",  // ❌ 不应该出现
    "some_random_field": "xxx"  // ❌ 不应该出现
}
```

**处理**：
- ✅ 白名单过滤
- ✅ 只保留8个核心字段
- ✅ 丢弃`old_topic_from_history`和`some_random_field`

---

### 情况2：用户输入模糊

**用户输入**：
```
帮我生成一个教案
```

**处理**：
- LLM可能无法提取明确的topic
- fallback机制：使用整个用户输入作为topic
- 不会触发全新需求判断（因为没有明确的topic变化）

---

### 情况3：部分字段更新

**用户输入**：
```
用户1：帮我生成一个函数单调性的教案，高一学生
用户2：改成高二学生
```

**处理**：
- 这是修改需求，不是全新需求
- 不触发净化逻辑
- `session["collected_info"].update({"student_level": "高二"})`
- 保留其他字段（topic仍然是"函数单调性"）
